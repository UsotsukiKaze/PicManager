# 图库校验、标签关联与设置

2026-10-03

## 两个校验状态

本地校验增加缓存标签检查：按图片已有分组、角色所属分组选择 Pixiv 映射，补齐缺少的特征标签、角色的父分组和 Pixiv 来源标签，并为已选标签建立明确的同名、别称或翻译关联。已缓存的原始标签缺失时，先从本地投稿快照补回；整个步骤无需连接 Pixiv，也不改变 Pixiv 校验时间。已有分组、角色和手动忽略保持不变；只有单页作品且角色为空、匹配唯一时才补角色，多页或映射冲突留待人工确认。重复运行不会追加重复关系。完成提示显示补充图片数、标签数、新映射和需确认图片数，仍沿用本地校验这一项状态。

新上传、temp 入库和优选夹草稿的年龄分级默认 R12；明确选择的全年龄、R16、R18 保留，Pixiv 限制作品继续使用 R18。历史图片和历史草稿的已保存分级不批量修改。

图片只展示本地校验与 Pixiv 校验两项状态，分别保存在 `images.local_checked_at` 和 `images.pixiv_checked_at`。时间为空表示尚未完成；`file_checked_at` 仅记录最近一次文件检查时间，不作为第三个校验标记。

本地校验依次归档缺失原图的记录、将没有数据库引用的文件移至 temp、检查原图尺寸和指纹、补齐缩略图，再调用现有重复图片审核。文件阶段按游标分批运行；重复图片的合并、保留为不同图片或暂缓由管理员选择。文件失败、归档和暂缓的图片不会获得完成标记。修改文件或影响重复比较的角色关联会使本地标记失效。文件指纹发生变化时清除旧 Pixiv 元数据和标记，允许重新校验。

Pixiv 校验包含投稿、页码、画师、高清和标签关联。新入库图片使用缓存的投稿数据完成元信息，不再次请求远端标签。已完成图片跳过远端检查；同名关联可读取已有缓存建立。不可用投稿保留检查时间避免反复请求，但不会显示为验证通过。旧高清完成时间及旧元数据验证时间在启动迁移时保留到统一标记；不伪造本地校验完成记录。

自动审核默认关闭，管理员可启用单页作品的自动确认。需要审核的作品在预览加载成功后开始 10 秒倒计时；页面隐藏时暂停，改动选择或查看本地图时取消当前自动确认。多页及无法明确对应页码的作品仍须手动选择；自动流程不补入额外页。高清替换继续经过后端尺寸和指纹检查。

## 并发队列与待确认列表

Pixiv 校验由后台线程池处理，默认 `PIXIV_CHECK_WORKERS=3`，范围为 1 至 6。任务清单保存在新增的 `pixiv_check_runs` 和 `pixiv_check_items` 表中，数据库原有记录不被重建。全局唯一活动批次和原子领取避免重复启动、重复领取；数据库租约限制同一批次的并发数量。每个线程复用自己的 HTTP 会话，令牌刷新单独串行，作品请求不持有全局账号锁，并继续遵守 `PIXIV_OL_REQUEST_INTERVAL` 和 `PIXIV_SCAN_INTERVAL_SECONDS` 限速。

需要确认页码或高清替换的图片进入待确认列表，释放工作线程，后台继续检查其他图片。待处理区提供“开始处理”入口，确认保存成功后自动打开下一张，并跨列表分页继续处理。“稍后处理，下一张”将当前作品留到下次处理；关闭窗口暂停连续处理，均不停止后台扫描。保存失败保留当前窗口和选择，重试成功后再进入下一张。刷新页面或切换页面后可恢复列表，已有的待确认作品不重复请求；确认结果写入后才获得校验标记。队列确认项保存 7 天，打开及提交时仍核对文件版本、账号和管理员权限；过期或已变化的图片需要重新校验。扫描进度包含“已发现待确认”的任务，因此扫描达到 100% 不代表这些图片已验证通过。

“停止”取消尚未完成的扫描任务，保留已完成结果和待确认作品。停止、图片修改或账号变更后，迟到的请求不能写入图片元数据。临时网络失败退避重试最多 3 次，单项失败不阻塞其他图片；账号或权限失效则终止本批次。正常关闭时进行中的任务重新排队，异常退出后过期租约在 5 分钟内回收；恢复时已提交的确认项直接复用。失败列表保留错误类别，重新开始校验会重试仍未完成的图片。无 PID 图片的轻量指纹由独立后台准备任务分批生成，不等待人工审核。

## 映射由图库实体管理

同一个 Pixiv 原始标签可以关联多个库内标签：例如 `kisaki（水着）` 同时关联“妃咲”角色和“泳装”特征，`anosoyo` 同时关联两个角色。关联窗口支持多选后一起保存，拖拽到另一个标签上追加关联；原始标签气泡展示所有已选关联。各实体的标签管理可以独立删除其中一条，不影响同名标签的其他关联。批量保存采用一个事务，目标失效时整批回滚。推荐搜索会复用同一原始标签并去重请求。

数据库以 `(normalized_tag, group_context, target_type, target_id)` 唯一保存各条关联，启动时迁移旧的单目标唯一约束，保留映射 ID、原始名称、来源、确认时间、实体外键和索引，不重建图库或改动图片标签。重复添加同一目标不会产生重复关系；忽略是对应上下文整体忽略，添加新关联会解除该范围的忽略。精确同名校验不会扩展或覆盖已有人为关联。默认添加是追加；API 的 `replace=true` 可明确替换同一范围的关联。

同一上下文中明确绑定的多目标一起匹配，不视为歧义；不同分组上下文对同一标签给出不同解释时继续待确认。角色的分组关联可同时使用全局的时装特征，同类型的分组内关联优先于全局关联。单页未确认草稿可以根据明确的组合标签补齐两个角色；手动已选角色、已确认分 P 和多页作品不自动扩展。旧图库已有角色仍保留，缺失特征可由缓存标签校验补充。

每次进入优选夹时，用投稿缓存和当前映射刷新标签草稿；普通读取及后台轮询不修改标签。草稿记录自动匹配标签与主动删除的建议，未确认的自动标签随映射更新或移除，保存时已选标签转为人工选择。新增映射可以补充新标签，手动添加和删除不会被同一建议覆盖；分 P 按各页的分组上下文处理，已确认角色不扩展为投稿其他角色。旧草稿没有来源记录时保留现有标签，并补充明确的新关联。入库中的作品不刷新，已提交任务使用提交时的标签；刷新不改变页码、已确认状态或自动勾选作品，也不调用 Pixiv 网络接口。

优选夹默认不勾选作品，保存标签草稿后自动勾选；分 P 作品在所选页的标签全部确认后才自动勾选。多 P 作品只选一页时直接按分 P 暂存，不询问加入方式。点击入库立即清除选择，作品转到悬浮球的后台入库队列；提交失败恢复选择与草稿，查重确认及失败重试在入库进度窗口处理。页面刷新后仍能从服务端任务恢复进度，旧的优选夹读取结果不能将已提交作品重新显示为待选。

图库缩略卡片左侧展示角色头像，右侧以深色显示角色名、下方显示分组名，裁剪缩略图铺满卡片，悬停或键盘聚焦时以亚克力底栏展开操作。两项校验状态移至管理员详情的信息卡片，不出现在缩略卡片上。详情沿用 Pixiv-ol 的两个独立卡片布局，图片居中、详情与图片顶部对齐；先展开模糊缩略图，再加载本地原图，支持关闭、相邻图片切换和加载失败重试。受限内容揭示后才请求原图，编辑、删除、下载保留原有权限流程。

设置页只配置推荐内容和参与的分组，不编辑映射。优选夹详情中的“关联已有标签”用投稿原始标签确认关联；保存后重新计算匹配并更新草稿选择。分组、角色、特征管理中的“Pixiv 标签”查看、修改和删除对应实体的映射，已关联标签以可移除的标签按钮排列。实体编辑窗分为基本资料与 Pixiv 标签页，基本资料的别称支持 Enter 或逗号添加、点击移除；打开关联编辑时保留尚未保存的基本资料。写入仅向 Root 开放，沿用现有权限。

`pixiv_tag_mappings` 保存原始标签 `original_tag`、匹配键 `normalized_tag`、分组上下文 `group_context`、来源 `source`（manual / exact）和确认时间。兼容原有 target_type / target_id，同时增加 group_id / character_id / feature_tag_id 三个实体外键和索引，由模型事件统一维护。角色映射绑定所属分组；角色迁移时映射随之迁移，存在目标分组冲突则拒绝修改并要求先处理映射。删除实体时删除对应映射，删除分组也清理该上下文的映射。旧表迁移补齐外键列并移除失效目标，重复启动可安全执行。

自动关联只接受启用推荐分组及旗下角色与 Pixiv **原始标签完全同名**的情况；不以翻译、近似或有歧义的同名项自动建立关联。已有手动关联和手动忽略优先；同名校验不覆盖它们。读取已有标签缓存也可建立关联，无需重新比对已入库图片的远端标签。

## 共用数据与导航

推荐设置直接复用分组、角色管理的完整分页数据。上方左侧展示 Pixiv 账号头像、昵称、连接状态，右侧配置内容偏好；下方分组选择在桌面按两栏排列，长名称换行。角色默认折叠，展开后展示该组全部角色；筛选角色时自动展开命中分组，清空筛选恢复之前的折叠状态。手机布局为单栏。分组筛选只影响本地显示。旧搜索词不再控制推荐请求，查询使用已有映射的原始标签或分组名，后续标签关联可以沿用同一映射表。

侧栏支持保存收起状态和过渡动画；Logo 与首页入口位于顶栏，用户头像、名称和权限位于左下角。顶栏“我的”和用户栏打开主界面中的个人中心，保留昵称、贡献统计、审核及管理员权限管理，退出入口继续保留。登录使用 QQ Ticket/SSO 授权，修改密码及默认密码提示已清除。

图片编辑窗收窄为 620px，将图片标签池和 Pixiv 原始标签分区展示；保留一个添加入口，打开选择窗时带入已有选择及分组约束。原始标签可点击或拖到池内标签建立关联，复用优选夹的交互及映射表。

旧图执行 Pixiv 校验时，从本地投稿或来源缓存补齐缺失的原始标签和 Pixiv 来源特征标签。已完成校验的图片不重新请求远端标签、不覆盖原始标签或分 P 角色，不改变校验日期。只有高清旧标记、尚无投稿元信息且没有缓存的记录进入一次投稿校验，补齐后不再请求。

启动迁移不会自动执行批量校验。旧图库需要由管理员在设置的维护操作中点击“本地校验”或“Pixiv 校验”。

## 投稿与画师

多页的预览下载失败、相似页无法唯一匹配、旧高清标记尚未确认页码时，仍进入人工待确认队列，不会当作校验完成或直接放弃。旧高清标记与缺少元数据的组合也能恢复既有审核；确认保存失败时窗口、页码和补入选择保留，成功后才关闭。补入页触发查重时，维护页继续显示补入任务、候选图片和继续操作；失败的补入任务可原地重试。

Pixiv 作品详情明确返回不存在（404）时立即清除当前图片的 PID；同一账号下、同一图片文件及 PID 的作品详情连续三次返回 `access_deny` / `access_denied`（包括作品不可见）时，也判为失效。前两次进入后台重试，第三次计入“清除失效 PID”，不进入失败列表。拒绝计数保存在任务结果中，可跨工作线程及服务重启恢复；其他错误、图片或 PID 变化都会重置连续计数。清理同时移除 Pixiv 元数据及来源关联，保留原文件和手动标签，并让它参与无 PID 特征索引。旧版本标记为 unavailable 的图片会重新查询后按该规则处理；账号授权失败、网络、限流、返回格式异常和不支持的作品类型不会作为作品失效。日志仅记录错误类别。

本地校验逐张提交，避免整批 200 张图占用 SQLite 写锁；指纹准备按单张短事务提交。空队列不发起领取 UPDATE。缩略图工作线程遇到数据库繁忙会继续重试，Pixiv 队列错误日志限频并带脱敏类别。游标接受大小写十六进制图片 ID。

Pixiv 原始标签属于整篇投稿，不能代表某一 P 的角色。首次校验、高清替换、旧图补全和再次导入已有图片时，保留该图片的手动分组、角色及特征标签；只同步原始 Pixiv 标签、画师、PID 和校验信息，并建立标签映射供入库时选择。分 P 入库只使用各页确认的标签，补入页沿用明确提交的草稿，不根据投稿标签再追加角色。同一作品不同页及同页多个本地版本都以独立 image_id 保存角色关系。

图片 PID 使用 `作品ID_pN`，从 0 计页。`pixiv_artists`、`pixiv_image_metadata` 和 `pixiv_check_reviews` 保存共享画师、投稿页和待确认校验；最后一张关联图片删除或更改 PID 后清理画师，不提供手动画师管理。多页校验由管理员确认对应页与补入页。读取远端时释放数据库事务，确认时重查管理员、账号版本、文件状态和审核期限。

详情沿用独立图片与信息卡片：图片在中轴，信息与图片顶部对齐；单页隐藏页数，作品标题和画师链接跳转 Pixiv。列表裁剪展示，悬停展开亚克力操作区。推荐分组区域默认收起，展开后仍采用两栏及角色折叠；关闭区域不改变选择。无 PID 指纹是辅助数据，不是第三个校验状态，见 [相似提示说明](pixiv-visual-similarity.md)。
