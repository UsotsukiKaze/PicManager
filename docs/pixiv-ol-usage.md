# Pixiv-ol 首版使用说明

多 P 作品首次加入优选夹时选择加入方式：**分 P 加入**逐页确认独立的分组、角色、特征和年龄分级；未确认的页会阻止统一入库。**合并加入**为所选页共用一套标签，图片仍按标准 `_pN` 分别保存。选择和逐页草稿保存在优选夹中，重新打开不会重复询问或覆盖已确认标签；旧草稿保持原有共用标签方式。分 P 条目展示各页的本地缓存缩略图与确认入口，入库时逐页使用所确认的标签，写入 Pixiv 元数据时也不会再把整组角色补回本地标签。

实现日期：2026-10-03。已完成本地自动化、真实账号连接、令牌刷新、推荐与关注更新读取及预览图片验证；统一入库尚未完成真实账号联调。

## 启动与连接

公网域名访问（包括在服务器自己的浏览器里访问域名）和经过反向代理的请求使用手动授权，不能自动唤起服务器上的 pixiv-cli。要使用本机自动回调，应在有桌面的服务器上直接打开 `http://127.0.0.1:<端口>`，并在运行服务的同一系统用户下安装 CLI。`data/pixiv-cli/` 不随 Git 分发，服务器首次部署后需要单独安装；现有安装脚本仅支持 Windows x64。已在服务器连接的 Pixiv 账号可供有权限的公网用户使用，无需在每台访问设备重新连接。

手动授权支持完整 HTTPS/Pixiv 回调、纯授权码，以及 Firefox 返回的 `https//app-api.pixiv.net/.../callback?code=...` 格式和地址栏省略协议的回调地址。粘贴时可带成对引号；程序只修正已知 Pixiv 回调的格式，不访问该链接。登录页、`/start`、`/post-redirect`、重复 `code` 或其他域名会被拒绝，输入格式错误不会消耗本次授权会话。部署更新后需重启服务，并刷新页面以加载更新后的登录脚本。

1. 更新依赖：运行 `uv sync`，随后按项目原有方式启动或重启服务。启动时自动创建新增表，并为旧图片表补齐校验字段；更新前备份数据库和图片文件。
2. 使用 Root 登录，打开侧边栏 **设置 → Pixiv**。
3. 点击“登录 Pixiv”。本机通过 `127.0.0.1` 或 `localhost` 直接访问时，优先使用固定版本 pixiv-cli v1.1.1。先运行 `python tools/install_pixiv_cli.py` 安装 Windows x64 官方发布包；安装器验证固定 SHA-256 并保留许可证。默认位置为 `DATA_PATH/pixiv-cli/pixiv.exe`，也可通过 `PIXIV_CLI_EXECUTABLE` 指定同版本程序。
   登录沿用系统默认浏览器现有状态。密码和验证码仅在 Pixiv 本站输入。若 Firefox 询问是否打开 Pixiv 应用，允许打开；系统 `pixiv://` 处理器会把授权送回仅监听 `127.0.0.1` 随机端口的本地桥接页。pixiv-cli 兑换并保存账号，PicManager 随后只导出本次登录的 UID，在内存中接收令牌并加密入库，不再重复兑换或立即刷新令牌。等待窗口显示进度，完成后自动关闭；刷新设置页可恢复进度。取消、超时或正常服务关闭会终止本轮子进程并移除本轮回调地址。
   pixiv-cli 在当前 Windows 用户下注册持久 `pixiv://` 处理器，并保留旧关联备份；它不是 Windows 自启动任务。CLI 的独立账号库位于当前用户的 `.pixiv-cli` 目录，因此不要更改该子进程的 USERPROFILE。协议处理器也使用同一目录；PicManager 数据库仍使用自己的 Fernet 密钥加密。原始 CLI 输出、verifier、授权码和令牌均不进入应用日志。
   未安装 CLI 或远程访问时保留手动回调模式：在当前浏览器完成授权，从开发者工具复制本次 callback URL 并立即提交。需要在本机完成的 CLI 登录不会在远程服务器弹出浏览器。旧的 Edge/Playwright `automatic` 模式仅保留 API 兼容性。
4. 展开默认折叠的“参与推荐的分组”，开启需要补图的分组。分组和角色与管理页共享，已有库存的分组默认开启；空分组需要手动开启。推荐配额根据库存自动计算，库存越少配额越大，不再手动编辑优先级。
5. 推荐页点击刷新，等待后台任务完成；关注页刷新新投稿，关注作者列表由后台定期同步。

## 新页面与优选夹

主页面只保留“为你推荐”和“关注更新”两项内容导航。右上角“优选夹”是当前管理员的暂存袋；账号和推荐参数在系统设置中的 Pixiv 区域，标签关联在优选夹和分组、角色、特征管理页完成。

1. 在画作卡片点击“加入优选夹”，或在详情里选择投稿页。此时只暂存，不创建图库记录或新标签。
2. 后台下载原图、校验格式和完整性，保存到 `TEMP_PATH/pixiv-ol/<暂存ID>/<页码>.img`。暂存清单和标签草稿保存在数据库，刷新页面与服务重启后可恢复。
3. 进入“优选夹”，通过“确认标签”调整入库标签和投稿页。已匹配标签自动进入草稿，已保存的人工调整在重新打开时保留。标签池只留一个“添加标签”入口，选择窗预选现有标签并按分组筛选角色；搜索和切换分组保留尚未确认的选择。选择窗也可新建分组、角色或特征，创建角色时带入当前分组。
   下方以气泡展示 Pixiv 原始标签。Root 可拖到标签池中的标签上建立关联，或点击气泡，从已加入标签池的标签中选择关联对象。关联直接保存并供后续匹配复用；标签草稿则通过“保存标签草稿”保存。匹配成功的气泡显示勾号与目标名称。旧草稿中的待创建特征标签继续保留，可单独移除。
4. 勾选缓存完成的作品，点击“统一入库”。提交前先验证全部草稿；每个作品各有持久后台任务，失败可以单独重试。批次不是全部作品共用一个长事务，已经成功的图片会保留。
5. 入库复用已校验的本地缓存，不重复下载，也不需要再次访问 Pixiv。全部选定页成功后移除该暂存项并清理它的 temp 缓存；未选定的暂存页也随该项移除，想保留时应一并选择入库。移除优选夹项同样清理它的文件。

默认总原图缓存容量为 2 GiB，每个管理员最多暂存 200 个作品，每次最多选 100 页；可通过 `PIXIV_OL_CART_MAX_BYTES` 调整容量。账号重新授权保留同一账号的暂存和偏好，切换 Pixiv 账号或解除绑定会清除账号对应暂存。缓存预览与文件仅通过管理员鉴权接口使用，不公开 temp 路径。

服务复用项目现有代理和请求超时配置；账号无法连通时先检查这些配置。首版只接入 Pixiv App API，不抓取 Web 发现页。

## 已实现功能

- Root 绑定单个账号，Root 与管理员使用；游客和普通用户没有页面、接口和预览权限。更换或解除账号会清除旧账号候选、关注和推荐缓存，并取消旧任务。
- “混合推荐”结合 App 推荐、分组搜索、已有收录投稿的相关作品和关注动态。“Pixiv 原生”保留最近成功获取的 App 推荐顺序。
- 分组库存按多分组投稿分摊，同一投稿的多页只计一次；配额使用 `(库存 + 5)^(-alpha)`，默认 `alpha=0.5`，补图权重比最多 4 倍，不采用旧的手动优先级。作者重复被软降权，无匹配分组的探索候选最多约 10%。候选不足时无法保证目标占比。
- 偏好统计按投稿 PID 合并多页，按分组计算标签均值并做小样本收缩；人工确认标签权重更高，Root 明确喜欢的反馈参与共享画像。管理员反馈与 Root 反馈分开保存。
- 本地分组别名、角色昵称、特征标签别名和确认映射自动匹配。歧义交由管理员选择，角色匹配受分组约束。
- 优选夹使用与上传页一致的标签池和添加窗口，Pixiv 原始标签通过拖拽或点击关联到已选标签，不再提供一键创建全部标签。入库支持选择投稿页、现有标签和年龄分级；Pixiv 成人分级作为最低限制。
- 后台入库先下载验证，再执行短事务；记录 `(Pixiv PID, 页码)`，重复提交保持幂等。精确文件重复复用已有图片，疑似重复等待人工选择。下载或数据库失败有重试与文件补偿。
- 关注动态分页续跑，首次回看七天，后续重叠回看两天；公共关注默认定期同步，私密关注需 Root 开启。默认动态同步间隔 30 分钟。

推荐批次保持固定顺序用于连续滚动加载，已入库页实时更新；下一次刷新推荐时移除已收齐的投稿。原生推荐与混合推荐分别缓存。

入库识别同时读取图库图片的 PID、Pixiv 校验信息和 Pixiv-ol 入库来源，无需先校验旧图片。`作品ID_pN` 按对应页识别；旧的纯数字 PID 默认代表第 1 页，原始文件名有匹配的 `_pN` 时按文件名页码识别。卡片和详情显示“已入库”或“已入库 X / Y 页”，收齐时禁用重复加入，部分入库只允许选择缺失页。从优选夹返回时使用轻量状态查询更新标记，并保留阅读位置。

## 数据与运行约束

- Refresh Token 使用独立 Fernet 密钥加密。默认密钥保存于 `DATA_PATH/.pixiv_ol_key`，也可配置 `PIXIV_OL_ENCRYPTION_KEY`。密钥不进入 Git；备份数据库时另行安全备份密钥，否则无法恢复账号授权。
- `PIXIV_OL_SYNC_SECONDS` 设置同步间隔；`PIXIV_OL_REQUEST_INTERVAL` 控制接口节流，默认一秒。请求错误只记录错误码，不保存授权响应正文。主登录流程使用 pixiv-cli 和系统默认浏览器，无需安装额外浏览器；Playwright 和 `PIXIV_OL_BROWSER_EXECUTABLE` 仅用于显式请求的旧版 `automatic` API 模式。
- 当前持久任务执行器按 **单 API 服务进程** 设计，请勿使用多个 Uvicorn worker 执行此功能。任务恢复、重试、账号切换依赖这一运行约束。
- 预览存放于 `DATA_PATH/pixiv_ol_previews`，临时下载存放于 `DATA_PATH/pixiv_ol_staging`。预览仅通过鉴权接口读取。目前没有自动磁盘配额/LRU 清理；规模增长时需要安排缓存清理策略。
- 当前仅支持静态插画/漫画图片，动画投稿不进入候选。每次入库最多选 100 页；需要不同页标签时分次提交。
- 页面沿用现有前端的懒加载模块；数据库迁移框架、整个前端重构仍按 [重构清单](refactoring-roadmap.md) 单独推进。

## 授权失败排查

回调链接只需复制并立即提交，不要先在浏览器中打开。回调页面自身返回 400 不能直接说明令牌兑换结果。兑换失败会区分授权码拒绝、客户端拒绝、服务端网络失败、上游服务故障与响应格式异常；失败会话不能再次兑换，弹窗提供“重新开始登录”。本地日志只记录兑换或账号连接阶段、错误类别、HTTP 状态与上游数字错误码，不记录授权码、verifier、令牌、完整登录 URL 或上游错误正文。授权兑换发送与 pixivpy 刷新流程一致的客户端时间与摘要头。

登录链路逐段核对、回调接收缺口与开源项目评估见 [登录检查报告](pixiv-ol-login-audit.md)。已接入 pixiv-cli 的 Windows 系统协议处理器及本地回调桥接，真实账号连接已验证。

Windows 回跳入口使用本项目虚拟环境的 `pythonw.exe` 静默启动官方 CLI，避免 CLI 的 Cobra 框架把 Explorer 启动当作双击命令行程序并提前退出。该入口不记录回调内容，也不使用 shell 拼接参数。虚拟环境或项目路径迁移后，需重新开始登录以更新当前用户协议关联。登录 CLI 被加入服务器拥有的 Job Object，异常结束服务器也会结束本轮 CLI；下次启动将旧会话标记为已中断，再重新授权。

Windows 中 `PIXIV_PROXY` 未配置时，默认通过 `PIXIV_USE_SYSTEM_PROXY=true` 沿用系统/环境的 HTTPS 或 HTTP 代理。显式 `PIXIV_PROXY` 优先；设置 `PIXIV_USE_SYSTEM_PROXY=false` 且留空 `PIXIV_PROXY` 时使用直连。CLI 兑换、API 刷新、推荐关注和 CDN 下载共用这一规则，不读取浏览器 Cookie，也不自动解析 PAC。当前自动选择与手动配置仅支持 HTTP/HTTPS 代理。固定版本 SDK 的 `pixiv:Complete: <reason>` 错误已分类为网络、授权码拒绝、限流、访问拒绝、响应异常及本地存储错误；页面与日志不显示原始错误内容。

## 图库校验、画师与详情卡片

维护操作中的 **Pixiv 校验** 检查有 Pixiv PID 的旧图。单页作品自动补全画师、Pixiv 来源标签和标准 PID；多页作品由管理员确认当前图片对应的页码，再勾选需要补入库的其他页。已有原图保留，高清替换须另行勾选，并通过尺寸和相似度检查。新增页使用原图片的分组和标签，提交后后台下载入库。无法访问的作品记录为不可用，继续检查其他图片。

新图片的 PID 采用 `作品ID_p0`、`作品ID_p1`，界面页码从第 1 页开始；上传官方文件名时可从文件名识别页码。非 Pixiv 标识保持原格式。校验和 Pixiv-ol 入库自动维护独立画师表，图库支持按画师 ID 或名称搜索，删除最后一张关联图片后清理该画师。Pixiv 原生标签可在详情查看，批量创建本地标签仍由管理员确认。

列表卡片裁剪展示图片，默认隐藏标签与操作按钮；鼠标悬停或键盘聚焦时作者区上移、按钮从底部出现，覆盖区域带亚克力虚化。触屏设备直接显示操作。卡片收窄以增加同时可见的图片数量，单页不显示 P 数。详情为两个独立、上对齐的卡片：图片保持页面水平、垂直居中，右侧信息卡片顶部跟随图片顶部，宽 300px，各自决定高度。画师展示头像和名称，点击跳转画师主页；Pixiv logo 按钮打开投稿页，关闭按钮位于图片右上角，点击两张卡片外的空白区域同样退出。喜欢可取消，切换推荐/关注页或刷新后恢复已保存的状态。

普通详情和优选夹详情改用 Pixiv master1200 清晰预览，保持比例并按页缓存，减少首次浏览时的下载量；原图下载仍用于暂存、入库和图库高清校验。翻页只保留图片两侧箭头与键盘方向键，信息卡片的勾选页仅用于选择要入库的页。详情先加载画师头像，再显示图片；旧缓存可复用同一画师其他作品的头像。头像使用独立下载并发，预览转成保留分辨率的 WebP，前端有按账号隔离、容量受限的内存缓存和相邻页预取。完整分组、角色和特征标签选择器支持搜索，不再截断到前 100 项。实现和验证记录见 [图库校验说明](library-validation-and-mappings.md)。


## 连续浏览与刷新

推荐与关注更新取消页码导航，每批加载 24 个投稿，接近底部时继续读取并去重；缩略图懒加载，离屏卡片延迟渲染。推荐固定当前批次，关注动态使用时间与 PID 游标，避免新投稿插入时重复或跳过旧内容。缓存接近读完时自动续拉；上游没有更多作品时保留刷新入口。

顶部显示绑定账号的头像和昵称；展柜外侧的独立悬浮按钮提供 PID 查找、换一批/更新动态以及回到顶部；下方保留优选夹入口。刷新执行期间禁用按钮，成功后加载新内容并回到顶部；其他入库任务完成不会重置正在浏览的列表。加入优选夹保留滚动位置，切换页面停止旧列表请求和滚动观察器。

同一媒体文件只下载一次，不同文件最多 4 路下载，画师头像有独立的 2 路额度；前端媒体内存缓存最多 40 项、48 MiB，切换账号或修改内容偏好时清空。

切换到“优选夹”再返回时保留推荐/关注更新的已加载列表、推荐批次、下一批游标和滚动位置；切换推荐方式或内容页分别保留各自进度，主动刷新后清空对应的旧列表。详情按作品记住上次阅读的页码。详情加入成功后按钮显示带勾的“已加入”，短暂确认后整个弹窗淡出；加入失败则保留详情和页码以便重试。

推荐和关注更新接近底部时提前加载下一页；当前本地缓存耗尽时自动排队向 Pixiv 续取，不清空已读列表或回到顶部。推荐沿 Pixiv 下一页游标继续生成新批次，关注动态继续读取更早的公开投稿（启用私密关注时也继续读取私密投稿）。重复作品自动跳过；上游确实无更多结果或连续多批无新作品时暂停，网络失败保留列表供重试。

详情标题直接链接 Pixiv 并保持标题字体；底部固定操作区中，加入优选夹/已加入按钮在左，喜欢按钮在右。加入优选夹与喜欢状态同一事务保存，重复加入不会创建重复反馈；重新打开详情或刷新页面后仍显示已加入。移除优选夹作品后询问是否同时取消喜欢，默认保留喜欢，关闭询问也保留喜欢。

点击画作时从卡片位置放大展开图片，详情卡片随后轻轻显现；展开期间先使用现有缩略图放大并模糊，中心显示星形与环绕圆点加载动画。画师头像完成加载前显示 PicManager 网站图标，清晰预览完成解码后淡入。翻页沿用上一张画面作为模糊占位，加载失败时保留占位并支持重试。系统开启减少动态效果时跳过展开和旋转动画。


## 无 PID 高相似提示与查找

执行 Pixiv 校验为无 PID 库图生成轻量指纹；推荐预览加载后只比较已有缓存，命中显示高相似并可查看库图，不自动补 PID 或合并。悬浮查找接受 PID、`PID_pN` 或 Pixiv 作品链接，预览后再决定是否加入优选夹。算法、成本和截图识别边界见 [相似提示与 PID 查找](pixiv-visual-similarity.md)。
