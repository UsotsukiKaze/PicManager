# Pixiv 推荐与双向收藏改造方案

日期：2026-10-14。状态：核心功能已实施；本文中的系数为实验初值，需要通过真实曝光和入库反馈进一步校准。

## 1. 核查结论与边界

- 本机 D:\A_Projects\PicManager 的 strategies.py 为 three-modes-v2，排序没有直接使用收藏数；工作区为 three-modes-v3 / stock-group-discovery-v1。实施时先核对并统一后端基线，不能只同步前端。
- 工作区 recent_popularity 在 1000 收藏封顶，无法区分同龄的 1000 与 10000 收藏作品。
- service.refresh_candidates 搜索未指定 sort；本机已安装 PixivPy 默认 date_desc。
- 现有画像已按作品聚合，但原始标签权重偏高，条件特征不足，加入优选夹自动喜欢会进入两个画像通道。
- 当前 feedback/mark_liked 仅写本地 PixivFeedback；没有调用远端收藏写接口。
- 已核对本机 PixivPy 和上游源代码：user_bookmarks_illust、illust_bookmark_detail、illust_bookmark_add、illust_bookmark_delete 均存在。列表有 restrict 与 max_bookmark_id，写入有公开/非公开和收藏标签参数。
- 这是接口能力核验，尚未进行真实账号读写验收；远端权限、网络和接口变化需在实施时验证。
- 同步对象为 Root 所绑定账号的小心心/收藏。优选夹是本地入库工作流；远端收藏不自动下载原图、不自动进优选夹、不自动入库。
- Pixiv App 推荐接口不能视为网页发现页的完整复刻。Pixiv 未公开可直接复用的完整现行排序模型。

## 2. 数据和画像

### 2.1 信号去重与可信度

同一账号、同一作品 PID 形成一个训练单元，多页不重复增加作品权重。明确的单页角色标签保留，以页内分摊后的作品级总贡献训练，不能将整部多角色作品的所有标签灌给每页。

同作品行为采用最高有效证据强度，而非跨来源相加：

- 手动小心心或 Pixiv 收藏：4；两端同步的是同一证据，只算一次。
- 人工确认入库：3。
- 仅在优选夹、随加入自动点亮心形：2。
- 旧图库批量导入、来源不明：1。
- 取消收藏是撤销正反馈，不是 dislike；明确不喜欢才硬排除。

自动加入产生的远端收藏回读必须保留 auto_cart 来源，不能升级为新的手动喜欢。旧反馈无法还原来源的保留 legacy_unknown，不伪造时间和动作来源。

有真实行为时间时衰减 d(t)=0.35+0.65*2^(-t/90)，t 为天。首次导入的远端旧收藏不以同步时间当作收藏时间；没有可靠时间就使用稳定长期权重，并分离 first_seen_at。

标签证据可信度初值：手动确认 1.0、明确 Pixiv 映射 0.9、角色继承特征 0.35、名称推断 0.25。映射是一对多，CP/换装标签允许映射多个实体，但单个标签贡献有总量上限。

### 2.2 标签向量

实体空间分为 group、character、feature、residual_raw。已解析为实体的原始标签不再在 residual_raw 重复加分；屏蔽 pixiv 标记、分级标记、热度标记和纯运营标签作为兴趣特征。

每个作品在一个实体空间内按匹配实体数量分摊贡献：

    C(t) = sum(work_weight * time_decay * evidence_confidence / entity_count)
    v(t) = log(1+C(t)) * clipped_idf(t)
    idf(t) = clip(log((N+1)/(df(t)+1))+1, 1, 3)

N/df 来自本账号缓存的去重候选语料，不能假装拥有全站频次；稀有标签有上限。每个空间单独 L2 归一化，作品匹配用余弦。

保留全局、分组、角色三级特征画像：

    F_group = n_g/(n_g+20)*F_group_observed + 20/(n_g+20)*F_global
    F_role  = n_c/(n_c+10)*F_role_observed  + 10/(n_c+10)*F_group

n 是有效的独立作品数。组合向量再归一化；候选有可靠角色则用角色画像，否则依次回退。对候选包含多个角色进行贡献分摊。

综合匹配初值：A=0.20G+0.30C+0.35F+0.15T。G/C/F/T 分别是分组、角色、条件特征、未映射原始标签匹配，均在 [0,1]。

探索池不要求已知角色，使用 A_explore=0.30G+0.55F+0.15T。跨分组探索使用 F/T，避免因为未知实体被机械判成差图。不同池分别排序，通过配额合并，不直接比较不同公式的裸分。

## 3. 候选召回

请求预算初值：原生推荐 35%、相关作品 25%、映射标签搜索 30%、榜单 10%。这是获取候选预算，不是展示配额；按成功率、重复率和实际入库收益调整，保留每路最低探索预算。

- 相关作品种子按分组、角色分层抽取 8–12 个，优先明确喜欢与精选入库，轮换使用；不再永远固定最靠前的 4 个。
- 搜索分别使用分组、角色、分组+特征、角色+特征；使用映射后的 Pixiv 原始标签。每条最多两个主要语义约束，避免过度 AND 无结果。
- 账户权限允许时使用 popular_desc，并分 7 天、30 天、历史时间窗；权限拒绝后记住能力状态并回退，避免每次失败重试。
- 无热门排序权限时用原生推荐、相关作品、榜单、分时段新作搜索补池，本地过滤质量。users入り 标签只做辅助渠道。
- 筛选年龄、屏蔽标签、AI 偏好；按作品去除已入库 PID、优选夹 PID、明确不喜欢和同批重复。
- 缓存热度快照、来源和推荐原始位次。来源缺失不能虚构一个排名100来加分。
- 标签映射版本和偏好版本进入候选/画像缓存键；改映射后重建本地匹配，不逐张重新联网取标签。

## 4. 质量评分

新增 total_view、total_bookmarks、sampled_at，以及榜单来源/位次。热门活跃候选低频再采样；没有两个可靠样本，不计算增长速度。

以相同分级、分组、发布时间段（0–2、3–7、8–30、31–180、180天以上）的候选为参照，至少50个有效样本，否则回退至更大分组；统计使用滚动历史池，不能每页重新计算导致分数跳变。

    P = 0.6*cohort_percentile(log(1+B)) + 0.4*global_age_percentile(log(1+B))
    rate = (B + 200*r0)/(V + 200)
    R = cohort_percentile(rate)
    velocity = max(0, B_now-B_previous)/elapsed_hours
    H = cohort_percentile(log(1+velocity))
    Q = 0.45P + 0.20R + 0.20H + 0.15K

B 为收藏数，V 为浏览数；r0 为相应参照组的稳健收藏率基线；K 为榜单表现 [0,1]。增长采样至少间隔6小时，统计下降/重置不产生增长。没有榜单来源记 K=0，而不是数据缺失；缺少浏览数/增长时用相应统计先验0.5，并记录置信度，不能按0惩罚，也不能仅把剩余强项放大。低曝光作品的 R 进一步收缩至0.5。

以上指标是热度代理，不等于审美真值。初始质量门槛：常规 Q>=0.50、组内探索 Q>=0.60、跨组探索 Q>=0.65；低置信候选保留小额实验位，后续按实际入库率校准。门槛不达标继续补池，不以低质图凑数。

时间采用候选分层：最近30天70%、31–180天20%、历史精品10%，属于可回退的软目标。缺新作时增加历史好图，不因发布时间新就给高质量分。

## 5. 三种排序与进货配额

### 猜你喜欢

    S_personal = 0.45*A + 0.35*Q + 0.20*N

N 为原生推荐/相关作品的来源内归一化位次分，纯搜索候选没有平台推荐证据时记0。不喜欢直接排除；浏览停留作为未来弱信号，不在首版把加载慢误判成喜欢。

### 进货模式

保留库存倒数规则。n_g 为该分组实际可用图片数，n_c 为角色图片数；同一图片对同一实体只计一次，多实体关联可分别计库存。已失效文件不计；训练按作品去重与库存按图片计数是不同用途。

    q_g = [1/max(1,n_g)] / sum_g[1/max(1,n_g)]
    q_c_given_g = [1/max(1,n_c)] / sum_c_in_g[1/max(1,n_c)]

角色数量 m_g<=20 的分组为稀疏组：

    e_g = min(0.80, 0.30 + 0.50*(21-m_g)/21)   if m_g<=20
    e_g = 0.30                                otherwise

新分组独立留5%，剩余95%再在参与分组内分配：

    p(new_group) = 0.05
    p(group_g, exploration) = 0.95*q_g*e_g
    p(group_g, known_role_c) = 0.95*q_g*(1-e_g)*q_c_given_g

有参与分组且各分组存在已知角色时，上述概率严格为1；探索占所属分组预算最高80%，不是额外叠加80%。零角色分组的已知角色份额进入未满足预算槽，不虚构角色、不突破80%上限，诊断显示需建立角色或调整模式。没有参与分组时不能应用该配额公式，提示选择分组并允许切换发现模式。组内探索优先分组映射标签下的高人气作品，已知角色按最近曝光给予惩罚。角色未识别是未知状态，不等同于确认的新角色。

组内质量优先排序：S_stock=0.60Q+0.25A_or_explore+0.15N。先决定桶，再取桶内最佳候选；库存缺口不能给低质量候选无限加分。

使用持续累计的加权欠额调度跨20张批次分配，避免每页整数舍入吃掉5%探索位。缺货桶保留欠额并触发补搜，有界补搜仍不足则返回不足量并记录原因，不悄悄把全部额度交给热门角色。仅有同模式合格缓存时可作为明确记录的回退。

### Pixiv发现与多样性

发现模式保留平台顺序，执行共同硬过滤，作为实验对照。

个人模式及进货桶内使用重排：S_final=S-0.12*max_tag_similarity_to_recent-0.06*recent_author_count；前20张同画师最多2张。个人模式同角色初始软上限5张；进货角色上限应服从其目标额度和容差，不能用固定上限破坏倒数配额。无替代合格候选时只放宽多样性，不放宽质量与内容过滤。

## 6. 双向收藏行为

| 操作 | POL | Pixiv |
| --- | --- | --- |
| POL 手动点心形 | 立即点亮，标记同步中 | 队列新增收藏 |
| 加入优选夹 | 保留现有自动喜欢；来源 auto_cart | 新增一次收藏 |
| 从优选夹移除 | 仍询问是否同时取消喜欢 | 只有确认取消才删除收藏 |
| POL 取消喜欢 | 二次确认，说明同步取消 Pixiv 收藏 | 队列删除；不删除图库或优选夹图片 |
| Pixiv 新增收藏 | 下次拉取后点亮，进入画像 | 保持原状态 |
| Pixiv 取消收藏 | 确认远端取消后熄灭，撤销收藏贡献 | 不反向重新添加 |

首次启用采用两端收藏并集，不按某一边缺失执行删除。支持公开/非公开两路拉取；POL 新增默认非公开，设置中可切换。远端已收藏时不重复 add，保留原可见性及收藏标签；不把本地分组/角色/特征当作远端收藏标签覆写。

远端取消只撤销收藏证据，已入库、仍在优选夹的独立证据保留。不会因下一轮读取优选夹就自动再次点亮，自动喜欢只能由“加入”动作触发。收藏同步不改写任何图片的人工标签。

## 7. 同步算法与持久化

### 数据表

- PixivBookmarkState：唯一(account_identity, pid)，local_desired、remote_observed、last_common、visibility、intent_version、source/provenance、first_seen_at、last_checked_at、remote_missing_state、tombstone。
- PixivBookmarkOutbox：唯一(account_identity,pid,intent_version)，action、status、attempts、next_retry_at、lease_until、sanitized_error。账号身份用已认证 Pixiv user_id + 本地绑定代次；令牌刷新不应清空身份。
- PixivBookmarkSyncRun：两路游标、扫描代次、起止时间、完整性、错误，支持断点续传。
- PixivArtworkMetric：pid、sampled_at、bookmarks、views；定期压缩历史样本。
- PixivRecommendationExposure：实际可见曝光、算法版本、候选来源、分项得分、主分组角色、后续行为；只生成卡片不算曝光。
- 原 PixivFeedback 扩展来源和动作信息；喜欢与明确不喜欢分开语义，现有行无损迁移。

### 出站

1. UI动作在同一数据库事务中写 desired + version 和 outbox；返回本地成功/待同步。
2. 单账号串行写，PID任务合并为最新意图；发送前检查版本和绑定身份。
3. 先查收藏详情：远端状态已一致则确认成功，不重写可见性/标签。
4. 调用 add/delete；超时不等于失败，先读状态确认，再决定是否重试。
5. 读取并确认远端最终状态，只有任务版本仍为最新才更新确认状态；点击时序发生变化则处理最新任务。
6. 重试采用5秒、30秒、2分钟、10分钟加抖动；429服从Retry-After；认证失效暂停队列并提示重连。进程重启通过租约恢复未完成任务。

### 入站

- 首次两路完整扫描，后台分页且可恢复；每次进入POL先刷新前几页，停留期间约5分钟增量检查；每日低优先级完整对账。这是项目调度任务，不是 Codex 聊天自动化。
- 列表接口没有可靠的逐条删除事件或变更时间，不能将“本页没看到”当成取消收藏。
- 只有公开+非公开完整扫描都成功才生成缺失候选；候选经第二次成功完整扫描并通过 bookmark_detail 明确未收藏才能撤销。账户认证失败、权限错误、作品不可访问均为 unknown，不执行取消。
- 网络故障期间保留上次成功快照；一侧隐私切换必须先在另一侧核对，不能误删。
- 三方合并比较 last_common、当前 desired 和 remote：仅本地变则推送，仅远端变则拉取，一致则确认；存在未完成的显式本地意图时以该意图优先。不假装凭本地时间能知道远端操作先后。
- 入站写入标记 origin=remote，不产生出站事件，防止循环同步；tombstone/版本防止旧快照复活已取消收藏。
- 双端同时操作且无法确定先后时在状态中显示冲突，提供保留本地/采用Pixiv；接口没有条件写和远端时间，不能承诺原子、即时的一致性。

### UI

设置增加双向同步开关、新增收藏默认可见性、首次导入/上传计数、立即同步、上次成功时间和失败重试。设置启用时先展示历史合并范围和默认可见性。

心形显示本地意图，并以小状态提示待同步/失败；只有远端确认成功才显示已同步。Pixiv收藏可通过本地收藏筛选查看，加入优选夹仍是显式动作。

## 8. 实施与验收

1. 统一后端基线、加迁移与版本化画像；保留数据库、密钥和资源。
2. 实现收藏镜像、出站队列、双路扫描及来源去重；先验证模拟API，再用用户授权的少量可恢复动作验证真实账号。
3. 增加候选来源、指标快照、条件画像和质量评分。
4. 实现严格归一化配额、跨批次欠额及多样性，接入前20张缓存首屏和后台补池。
5. 新旧策略使用相同候选集做离线比较，再以可见曝光做分批在线比较，避免把来源差异误当排序提升。

必须覆盖：多P不重复训练；复合映射无串角色；自动喜欢回读不双计；1000与10000收藏可区分；新作/旧作/冷门小样本回退；概率和=1；80%为组内预算；20张分页探索不丢失；低质量不凑数；已入库/优选夹过滤；公开转私密不误取消；扫描中断不删除；快速喜欢-取消-喜欢最终一致；同步超时/429/401/重启恢复；换账号隔离；远端作品不可访问不当作取消；取消收藏不删除本地图片。

记录前20张加入率、每100次可见曝光入库率、分组/角色覆盖、质量分分布、重复率、首屏延迟与同步积压。参数仅写在算法配置和诊断中，不向普通推荐页面展示。
