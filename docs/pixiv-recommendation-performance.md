# POL 推荐生成与接续提速

2026-10-14。优化的是换一批和继续下滑时的作品信息生成；图片媒体下载继续使用独立连接池。

## 已实现

- 每次仍展示 20 张。当当前推荐批次剩余不超过 40 张时，提前请求后继批次。后继批次暂存于该模式的阅读状态，不提前插入 DOM、不改变滚动位置、不计入曝光。换一批优先消费已经准备好的批次，也可接管正在准备的任务。
- 提前请求携带当前批次 ID。服务端校验账号、模式和用户归属，将当前批次全部作品加入排除集合，防止尚未读到的卡片在后继批次重复。收藏和库内排除仍在取分页时执行。
- 推荐任务和原图缓存/入库/收藏同步分为两个工作通道；每个通道串行领取持久任务。手动刷新优先于预取和后台补充。同模式的游标更新继续串行，不无限增加 API 并发。
- 账户 JSON 状态的读写由短事务锁保护，网络请求在事务外执行；元数据网络请求使用独立锁。令牌轮换按读取最新凭据、认证、保存结果串行执行，调用方不在持有账户锁时等待认证，避免锁顺序反转和重复使用失效的刷新令牌。
- 在内存中缓存尚未到期的访问令牌，提前 60 秒失效，最多保留 32 个缓存键。刷新令牌原值不作为缓存键，不共享 HTTP 会话；代理、请求超时、访问令牌过期或认证拒绝都会影响复用。没有可信过期时间时不缓存认证。
- 标签匹配使用有界缓存，以名称、映射、角色关系版本和原始标签/分组上下文为键；返回独立结果，编辑映射后不会继续命中旧结果。字符串规范化也使用有界缓存。
- 一轮召回和最终排序共享偏好画像；期间标签配置变化则重新计算。作品与热度样本改为批量读取和写入，减少逐作品查询与 flush。
- 候选先按来源批次过滤，再应用候选预算。收藏同步更新抓取时间不会把当前批次排除在“最近 1000 条”的窗口之外。SQLite 使用 JSON 来源条件在数据库侧筛选；其他方言使用分批迭代回退。
- 推荐任务以独立的 500ms 状态查询确认就绪，不等待收藏和优选夹轮询。分页只返回卡片所需数据，不发送完整推荐画像。保留普通轮询，无新增 SSE 部署要求。
- 推荐任务结果记录 queue_ms、auth_ms、work_ms，以及画像、召回、排序的分段耗时；不包含授权信息。

## 性能检查

本机现有数据库只读分析：174 张库图、约 1.15 万作品记录、2447 条喜欢。8777 在检查时没有运行，以下只比较本地计算，不代表 Pixiv 公网端到端耗时。

| 操作 | 优化前 | 优化后 |
| --- | --- | --- |
| 猜你喜欢排序，两轮 | 1.50 / 1.32 秒 | 1.21 / 0.99 秒 |
| 进货模式排序，两轮 | 1.70 / 1.70 秒 | 1.15 / 1.15 秒 |
| 发现模式本地处理，两轮 | 0.156 / 0.160 秒 | 0.032 / 0.031 秒 |

该比较还包含候选窗口修复，优化后可能处理更多合格候选，不能视为完全相同候选数量的微基准。提前补充和任务隔离的体验收益由回归验证：原图任务等待时推荐仍能完成；预取就绪后换一批不再发起远程刷新；首屏依然只显示 20 张。

首次冷启动、候选被过滤殆尽、快速连续换批或远端限流时仍可能等待。当前预取阈值为固定 40 张，尚未按浏览速度自适应；没有降低质量门槛或改变进货探索配额来凑满数量。

## 本机真实账户检查

同步源代码和前端构建后，将本机两份旧 8777 监听合并为单实例，已确认新增状态接口生效。重启前保留了一致性数据库备份。

通过当前账户执行一次猜你喜欢首批刷新及一次后继预取，不改变远端收藏或导入图片：

| 阶段 | 首批刷新 | 后继预取 |
| --- | --- | --- |
| 用户请求到完成状态 | 2.52 秒 | 3.91 秒 |
| 生成作品 | 28 张 | 35 张 |
| 任务排队 | 2ms | 4ms |
| 取得认证客户端 | 43ms | 42ms |
| 构建画像 | 737ms | 630ms |
| 远程召回及落盘 | 886ms | 2642ms |
| 排序 | 440ms | 385ms |

首批取 20 张分页为 15ms。这是当前代理路径的一次运行结果，不能视为公网延迟保证，也没有相同远程响应的优化前对照。后继任务仍需要生成时间，提前准备的用途是把这段等待移到阅读当前批次期间。
