# 无 PID 图片相似提示与 PID 查找

## 使用

在维护操作中执行一次“Pixiv 校验”，为可用的无 PID 库图分批生成视觉指纹。每批最多 24 张，优先读取有效缩略图，未生成缩略图时读取本地文件；这一步不需要连接 Pixiv，不下载任何图片。之后推荐、关注更新和 PID 查找详情在预览加载后后台比较已有缓存，命中时显示“高相似”，详情可打开相似库图。

POL 展柜旁的悬浮操作增加“按 PID 查找”。接受数字作品 ID、`作品ID_pN` 和 HTTPS Pixiv 作品链接；`pN` 从 0 开始。查询后打开现有详情窗，由用户决定是否加入优选夹，保留多 P 的页码和分 P／合并选择流程。单纯查询不添加优选或喜欢；加入时沿用自动喜欢、已加入状态和关闭动画。关闭查询会取消等待，15 秒未返回可重试。

## 指纹与成本

`image_visual_fingerprints` 是图片的一对一附属表，保存算法版本、原文件路径／尺寸／修改时间签名和小尺寸描述。图片删除时清理；修改 PID 或文件元信息时失效。它不增加校验状态，不设置本地或 Pixiv 校验完成标记，也不自动推断 PID、覆盖或合并图片。

仅使用现有 Pillow 和 Python 标准库。图片缩至最多 256×256，生成最多六个区域：整图、均匀截图背景上的主要内容、中心轻裁切和中心正方形。每个区域保存 63 位感知哈希、64 位差分哈希、16×16 灰度网格、4×4 颜色网格及宽高比。纯色及缺少结构的区域跳过。超过 5000 万像素或不可读文件记录失败，避免每批反复尝试；文件经本地校验修复或文件元信息更新后重新生成。

服务进程缓存索引，数据库版本变化时重建。七段哈希倒排索引筛出感知哈希距离不超过 6 的候选；每个区域最多复核 256 个候选，再要求宽高比接近、差分哈希距离不超过 10、灰度相关性至少 0.94、颜色平均差不超过 22。每个作品最多提示三个库图。匹配前确认本地文件签名仍有效。

本机合成画作测试：描述约 3 KB／图，平均计算约 27 ms／图；一万张图片、每张六个区域的索引构建约 258 ms，六次哈希候选查询约 4 ms。上述数字不含磁盘读取、网络和候选结构复核，不代表全部图库的固定耗时。

## 预览与权限

`GET /api/pixiv-ol/similarity` 每次最多 24 个 PID。仅比较当前账号及内容偏好允许的投稿，并仅读取已缓存的第 1 页预览；有清晰详情预览时优先使用。前端在图片加载后合并请求，不阻塞首屏、不为相似检测额外下载原图。结果只返回本地图片编号及结构分数，不包含本地文件路径。

`POST /api/pixiv-ol/lookup` 沿用管理员权限、来源校验和当前账号隔离。已有投稿缓存优先使用，否则经现有客户端读取投稿详情；保存和展示前重新检查账号版本及内容限制。两接口响应沿用 private/no-store，不向前端提供远端原图地址。

“高相似”是人工核对提示，支持不同分辨率、常见留白或界面栏截图。严重裁切、遮挡、滤镜及多 P 中非首页可能漏检；结构相近的作品仍可能误报。分数不是相同来源的概率，不以此建立 Pixiv 校验通过标记。
