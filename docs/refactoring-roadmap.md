# 数据库与前端重构事项

记录日期：2026-10-03。状态：待实施。本文记录本轮讨论的优化方向，不代表业务重构已经完成。

实施进展：Pixiv-ol 已作为现有前端的独立懒加载模块接入。原有缩略图/预览任务执行器已拆为短事务领取、事务外生成、短事务写回；Pixiv 下载同样采用这一方式。统一业务事务所有权、数据库迁移框架和完整前端重构仍待实施。

## 已有基础

保留现有 FastAPI 服务、SQLAlchemy 模型、本地/R2 存储接口，以及登录、审核、查重和机器人集成。现有分页、缩略图懒加载、实体请求去重、缓存失效版本、SQLite WAL、busy timeout 和备份逻辑继续复用。

## 数据库与业务事务

| 顺序 | 事项 | 完成条件 |
| --- | --- | --- |
| P0 | 拆分图片任务事务：短事务领取并提交，事务外下载/解码/编码，短事务写回结果 | 慢任务运行期间其他登录、上传、编辑仍能写入；租约和异常恢复通过测试 |
| P0 | 统一事务所有权，减少 Service 内部 commit，由用例入口统一提交图片、任务和审核状态 | 一次业务操作中途失败后没有部分提交；需要提前独立提交的事务必须明确标注 |
| P0 | 文件发布增加补偿：提交前保留暂存源，失败后恢复或清理目标；提交后再清理源 | 模拟数据库锁、远端失败和进程重试，不丢暂存源、不生成无人管理的对象 |
| P0 | 修复派生图片分发与删除、R2 故障误判、远端删除和缩略图维护 | 删除后受限预览不能匿名访问；远端超时不能触发记录删除；删除和重建支持两种后端 |
| P1 | 图片和实体列表排查 N+1；集合关系评估 selectinload，补齐昵称/别名预加载 | SQL 次数不随列表条目数线性增长；多标签图片不造成过大的连接结果 |
| P1 | 图片列表提供轻量数据结构，详情单独加载 | 保持现有接口兼容，新前端卡片不接收完整关联实体描述和时间字段 |
| P1 | 贡献榜改为数据库聚合；浏览和角色查询计数使用原子增量 | 排名不拉取全部审核历史；并发计数没有读改写导致的覆盖 |
| P1 | 慢查询测量与组合索引评估 | 保存 SQL 次数、查询计划和前后耗时，避免与已有索引重复 |
| P2 | 深分页评估游标分页；随机抽图避免每次加载全部候选 ID | 稳定排序、无遗漏/重复；保留明确的随机分布与近期去重规则 |
| P2 | PID 查询增加明确的精确/前缀模式；描述检索随数据增长评估专用索引 | 不静默改变现有包含匹配语义；中文检索保持可用 |
| P2 | 将增量迁移整理为可版本化、可测试的迁移流程 | 新库与旧库升级均通过；回滚和备份方案明确 |
| 条件项 | PostgreSQL 迁移 | 仅在持续并发写入、多实例部署等需求出现后评估；当前 PRAGMA、INSERT OR IGNORE 等 SQLite 专用代码需先解耦 |

索引候选包括任务领取 `(status, available_at, id)`、审核列表按状态/提交者/时间的组合，以及确有收益的年龄筛选与排序组合。现有图片状态排序索引和角色、分组、特征关联表反向索引已经存在，不重复添加。

计数如采用异步批量写回，必须先确定是否允许短暂延迟，以及进程退出时的持久化和冲刷规则。

## 前端重构

拟采用 **Vue 3 + TypeScript + Vite 的 SPA**，保留 FastAPI API 和当前视觉风格。框架迁移用于改善组件、状态与类型管理；性能收益仍需单独测量。

| 部分 | 方针 |
| --- | --- |
| 路由 | Vue Router；图库、上传、表情、个人中心、审核和 Pixiv-ol 独立路由，功能按需加载 |
| 应用状态 | Pinia 管理身份、持久筛选偏好和上传队列；页面临时交互使用组件状态 |
| 服务端数据 | TanStack Vue Query 管理图库、角色、标签和 Pixiv 候选缓存，不在 Pinia 中重复保存同一份数据 |
| API | 按领域组织类型化客户端；由 OpenAPI 生成或校验契约；兼容 Cookie 会话和现有接口前缀 |
| 搜索 | 取消过期请求、忽略过期响应、输入防抖；AbortError 不提示为网络故障 |
| 选择器 | 限制初始选项数量、按分组加载，数据变大时增加服务端搜索与虚拟列表；已选择项独立保存 |
| 图片列表 | 轻量卡片数据、保留加载中的旧结果、懒加载和异步解码；维持受限内容揭示与鉴权规则 |
| 缓存 | 按实体与查询条件设置缓存；增删改精准失效；账号切换清理身份相关缓存 |
| 上传 | 队列状态与上传任务逻辑独立于页面；保留进度、失败重试、查重和审核反馈；修复 R2 CSP 与错误回退 |
| 组件 | 提取 ImageCard、ImageDetail、TagPicker、EntityAvatar、UploadQueue、DuplicateReview、ReviewDiff 等公共组件 |
| 部署 | Vite 产物使用内容哈希文件名；同源部署减少 Cookie/CORS 改动；SPA 回退不能覆盖 API、登录及资源路由 |
| 测试 | 核心组件行为与状态测试；登录、搜索、上传、查重、审核和账号切换使用浏览器端到端测试 |

建议组织：`frontend/src/{api,components,features,composables,stores,router,styles}`，领域模块包括 gallery、upload、emoji、review 和 pixiv-ol。

## 实施顺序与验证

1. 先完成 P0 稳定性与一致性修复，并修复图片分发测试的临时数据库 fixture。
2. 建立新前端壳、路由、API 契约和登录状态，优先迁移图库浏览与搜索。
3. 迁移上传、查重和表情包，再迁移个人中心与审核。
4. Pixiv-ol 采用独立领域模块，见 [功能设计](pixiv-ol-design.md) 与 [推荐/数据挖掘补充](pixiv-ol-recommendation-design.md)。可先补充后端适配器与候选模型，不要求整站前端迁移完成后才开始。
5. 根据实际数据量优化深分页、随机抽图、聚合与索引。

测量指标：搜索/详情接口 P50、P95，SQL 次数、响应体大小、SQLite 锁等待和错误数、角色选择器 DOM 数与输入响应时间、上传耗时与后台队列延迟。前轮干净工作树测试基线为 233 passed、3 failed；这不是本次文档修改后的重新测试结果。
