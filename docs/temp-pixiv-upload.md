# Temp 上传与 Pixiv 预校验

只处理应用配置的 `TEMP_PATH`（默认 `resource/temp`），不扫描外部日常存图目录。预校验不改名、不删除、不替换图片，也不自动入库。

## 操作

打开上传页的 Temp 标签页后，自动预校验。缩略卡默认不选中；点击图片打开左右排列的本地原图和标签信息。已有映射的分组、角色、特征自动填入标签池，用一个“添加标签”入口编辑。Pixiv 原始标签与优选夹共用点击 / 拖拽关联操作；保存映射仍由 Root 操作。

确认标签后自动选中，点击“入库所选”立刻清除选择并转入悬浮上传队列，默认两个上传任务并行。重复图片沿用现有查重确认，不丢失已确认的标签；取消或失败恢复选择，可在队列重试。标签草稿在当前页面会话中保留，刷新浏览器后需要重新确认。确认入库仍沿用 Temp 上传原有文件入库行为。

详情从所点卡片展开，先使用模糊缩略图与加载动画，原图解码后淡入；减少动态效果模式跳过展开动画。信息区底部左侧为“确定信息”，右侧为垃圾桶按钮；删除前需二次确认，取消删除保留编辑内容，失败可重试。

桌面详情为独立的图片卡片和信息卡片，无共用外框。信息卡片宽度、横向位置和底部操作位置固定；字段在卡片内部滚动。左侧图片按宽高比适配可用空间，靠近信息卡片、独立垂直居中。手机端上下排列，标签窗口仍沿用原有弹窗。

## 识别和页码

- `作品ID_p0`、`作品ID_p1_master1200` 等文件名带明确页码；纯数字文件名和图片头部的 Pixiv 来源链接作为作品线索。不会把普通画师名或任意数字都当成 Pixiv ID。
- 查作品详情后，明确页码用对应页清晰预览和本地文件的 dHash 比较，不下载整件作品的原图，也不使用 OCR 或大型向量模型。
- 无页码的单页作品可以确定 p0；多页作品不默认猜成 p0。图像不匹配、预览下载失败或页码不明时保留“待确认”，由用户选择对应页并勾选核对。
- 多页作品匹配到多个角色时，先填分组和特征，角色由用户按当前文件选择。每个文件独立确认，不把整件作品的角色自动合并进当前页。
- 入库后保存标准 `作品ID_pN`、画师、Pixiv 原始标签、Pixiv 图库标签和统一的 Pixiv 校验位；不会覆盖用户确认的角色。不自动标成本地校验完成或高清补全完成。

## 队列与取消

每个页面会话按文件串行预校验，整个实例最多两项联网预校验并行；复用本轮 API 客户端和既有 CDN 下载池。严格按列表顺序处理文件，逐张更新结果；已完成的图片可以立即编辑，无需等整批结束。已完成结果在内存中按账号、用户、文件大小和修改时间缓存，最多 512 项、30 分钟；标签建议每次按当前实体和映射重算。

离开 Temp 标签页、离开上传页或关闭浏览器页面时，中止前端请求并停止本轮服务端会话，不再派发剩余文件。已经发出的上游请求最多等到请求超时，但停止后的结果不能继续写入预校验缓存或作品表。断线未正常发送停止时会话租约失效，下一次进入回收旧客户端。入库任务与预校验分开，离页不会取消已经确认的上传。

原图仅管理员可读；列表使用最大 500px 的鉴权缩略图，源文件变化后更换缓存标识。提交时复核预校验凭据对应的用户、账号版本、文件和页码，过期或变化时要求重新预校验。服务重启后预校验凭据失效，图库内已经落库的校验信息保留。不新增数据库表。
